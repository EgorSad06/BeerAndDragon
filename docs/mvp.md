# Зафиксированный MVP (версия 0.1)

MVP — минимальный набор функций, без которого не проходится [основной сценарий](requirements.md#3-основной-сценарий-mvp):
**передвижение → бой → предметы → смерть/перезапуск**. Всё остальное — резерв: не блокирует релиз 0.1
и делается, если остаётся время.

Состояние зафиксировано **по коду в ветке `debag` (коммит `f6966ba` и далее)**. Изменение состава MVP — только через PR,
который правит этот файл (см. [repo-rules.md](repo-rules.md)).

## Резерв (не входит в MVP)
| Функция | Почему в резерве | Статус |
|---|---|---|
| Скейт: трюки, грайнды, очки, звуки Jet Set Radio (FR-SK-01…06) | «фишка» игры, но основной сценарий проходится без неё | ✅ уже работает, доводится по отзывам |
| Модель рыцаря с процедурной анимацией, вид от 3-го лица (`V`) | визуал, на геймплей не влияет | ✅ работает |
| Дырки от пуль через пул объектов (SP-1, [system-programming.md](system-programming.md)) | оптимизация; сейчас декали работают через `Instantiate/Destroy` | 🔨 модуль пула готов, подключение к `Weapon` — следующий шаг |
| Пакетные рейкасты дробовика через Job System (SP-2) | оптимизация | 📋 запланировано |
| Враги с ИИ | большой объём работы; для MVP хватает мишеней (`Damageable`) | 📋 запланировано |
| Меню, настройки, сохранения | для демо-уровня не обязательны | 📋 запланировано |
| Несколько уровней | MVP — один уровень-песочница `SampleScene` | 📋 запланировано |
| Звук оружия и шагов, музыка | — | 📋 запланировано |

## Критерий «MVP готов»
1. Все FR из таблицы «Обязательно» проходят свои критерии проверки (автотесты зелёные, ручные проверены по [чек-листу](repo-rules.md#3-definition-of-done-dod)).
2. Конвейер `main.yml` зелёный: сборка Windows + тесты.
3. `release.yml` по тегу `v0.1.0` проходит Release Gate (NFR-01…06).
