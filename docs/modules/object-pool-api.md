# Справочник API модуля ObjectPool

Сгенерировано из XML-документации компилятора (`dotnet build tools/pz02/PoolDoc`, `python tools/pz02/docgen.py`). Контракт словами — [object-pool.md](object-pool.md).

## `IObjectPool<T>`

Пул переиспользуемых объектов с жёстким лимитом (модуль SP-1, контракт — docs/modules/object-pool.md).
Решает задачу: выдавать объекты (декали, вспышки, гильзы) без создания и уничтожения на каждое событие
и никогда не держать больше `Capacity` объектов.

**Владение.** Пул владеет всеми созданными им объектами. Выданный объект потребитель использует,
пока не вернёт его через `Release`; после возврата, а также после принудительного
переиспользования (`ReuseOldest`) ссылку держать нельзя — объект снова принадлежит пулу.

**Побочные эффекты.** Только вызовы фабрики `create` и обратных вызовов `onGet` / `onRelease`,
переданных при создании пула. Сам пул не выполняет ввода-вывода, не обращается к движку и не пишет журнал.

**Потоки.** Не потокобезопасен: вызывать только из главного потока Unity.

**Реализации.** `BoundedPool<T>` — без выделений памяти после прогрева, переиспользование O(Capacity);
`LinkedPool<T>` — переиспользование O(1), но каждая выдача выделяет узел списка.
Наблюдаемое поведение (результаты и ошибки) у них одинаковое; различаются только время и память.
Реализацию выбирает точка сборки `ObjectPoolFactory`.

**Пример**
```csharp
IObjectPool<GameObject> pool = ObjectPoolFactory.Create(PoolKind.Bounded,
() => Object.Instantiate(prefab), capacity: 60,
onGet: go => go.SetActive(true), onRelease: go => go.SetActive(false));
GameObject hole = pool.Get();   // лимит исчерпан -- вернётся самый старый объект
pool.Release(hole);            // повторный Release(hole) -- InvalidOperationException

```

- **`Capacity`** — Наибольшее число объектов, которое пул может создать; задаётся при создании, > 0.
- **`CountActive`** — Выдано и не возвращено. Всегда `CountActive + CountInactive == CountAll <= Capacity`.
- **`CountInactive`** — Создано и лежит в пуле свободным.
- **`CountAll`** — Всего создано пулом и ещё не потеряно; никогда не превышает `Capacity`.
- **`CreatedTotal`** — Сколько раз за жизнь пула вызывалась фабрика `create`.
- **`Recycled`** — Сколько раз сработало переиспользование самого старого объекта (`ReuseOldest`).
- **`Get`** — Выдать объект. Порядок: свободный объект (последний возвращённый) → новый объект, если `CountAll < Capacity` → при исчерпанном лимите по политике: `ReuseOldest` — самый давно выданный объект, `Fail` — `null` без изменения состояния. Для выданного объекта всегда вызывается `onGet`.
  - результат: Объект, принадлежащий пулу, или `null` (только при `Fail`).
  - ошибка `InvalidOperationException`: Фабрика `create` вернула `null`.
- **`Release(…)`** — Вернуть выданный объект в пул; для него вызывается `onRelease`. Ошибки проверяются в порядке: `null` → объект не из этого пула → объект уже возвращён. При ошибке состояние пула не меняется.
  - `item`: Объект, полученный из `Get` этого пула и ещё не возвращённый.
  - ошибка `ArgumentNullException`: `item` равен `null`.
  - ошибка `InvalidOperationException`: Объект создан не этим пулом, или уже возвращён.
- **`Prewarm(…)`** — Создать заранее `min(count, Capacity)` объектов (всего, с учётом уже созданных); они остаются свободными.
  - `count`: Желаемое число объектов; отрицательное и нулевое ничего не делает.
- **`IsActive(…)`** — `true`, если объект сейчас выдан этим пулом; для `null` и чужих объектов — `false`.

## `PoolOverflow`

Что делает пул, когда все `Capacity` объектов уже выданы.

- **`ReuseOldest`** — Забрать объект, выданный раньше всех: для него вызывается onRelease, затем он выдаётся заново.
- **`Fail`** — Не выдавать ничего: `Get` возвращает `null`.

## `BoundedPool<T>`

Реализация `IObjectPool<T>` без выделений памяти после прогрева (модуль SP-1).
Свободные объекты — в стеке, выданные — в словаре «объект → номер выдачи»; самый старый ищется
линейным проходом по выданным, поэтому `Get` при переполнении стоит O(Capacity).

Все коллекции создаются сразу ёмкостью `Capacity` и не растут, поэтому после
`Prewarm` вызовы `Get` / `Release` не выделяют память в управляемой куче
(проверено тестом `BoundedPoolTests.SteadyState_GetRelease_DoesNotAllocate`).
Поведение — по контракту `IObjectPool<T>`.

- **`Capacity`** — см. `IObjectPool<T>`
- **`CountActive`** — см. `IObjectPool<T>`
- **`CountInactive`** — см. `IObjectPool<T>`
- **`CountAll`** — см. `IObjectPool<T>`
- **`CreatedTotal`** — см. `IObjectPool<T>`
- **`Recycled`** — см. `IObjectPool<T>`
- **`конструктор(…)`** — Создать пул. Объекты не создаются, пока не вызван `Get` или `Prewarm`.
  - `create`: Фабрика объекта; не должна возвращать `null`.
  - `capacity`: Лимит объектов, > 0.
  - `overflow`: Что делать при исчерпанном лимите.
  - `onGet`: Вызывается для каждого выдаваемого объекта (необязательно).
  - `onRelease`: Вызывается для каждого возвращаемого и забираемого объекта (необязательно).
  - ошибка `ArgumentNullException`: `create` равен `null` (проверяется первым).
  - ошибка `ArgumentOutOfRangeException`: `capacity` <= 0.
- **`Prewarm(…)`** — см. `IObjectPool<T>`
- **`Get`** — см. `IObjectPool<T>`
- **`Release(…)`** — см. `IObjectPool<T>`
- **`IsActive(…)`** — см. `IObjectPool<T>`

## `LinkedPool<T>`

Вторая реализация `IObjectPool<T>`: порядок выдачи хранится в двусвязном списке,
поэтому переиспользование самого старого объекта — O(1) (первый узел списка), а не линейный поиск.

Цена: каждый `Get` добавляет в список новый узел `LinkedListNode<T>` — выделение памяти
в управляемой куче на каждую выдачу (в отличие от `BoundedPool<T>`). Результаты и ошибки — те же,
что требует контракт `IObjectPool<T>`; проверяется общим набором тестов `ObjectPoolContractTests`.

- **`Capacity`** — см. `IObjectPool<T>`
- **`CountActive`** — см. `IObjectPool<T>`
- **`CountInactive`** — см. `IObjectPool<T>`
- **`CountAll`** — см. `IObjectPool<T>`
- **`CreatedTotal`** — см. `IObjectPool<T>`
- **`Recycled`** — см. `IObjectPool<T>`
- **`конструктор(…)`** — Создать пул; параметры и ошибки — как у `BoundedPool<T>`.
  - ошибка `ArgumentNullException`: `create` равен `null` (проверяется первым).
  - ошибка `ArgumentOutOfRangeException`: `capacity` <= 0.
- **`Prewarm(…)`** — см. `IObjectPool<T>`
- **`Get`** — см. `IObjectPool<T>`
- **`Release(…)`** — см. `IObjectPool<T>`
- **`IsActive(…)`** — см. `IObjectPool<T>`

## `PoolKind`

Какую реализацию `IObjectPool<T>` создаёт `ObjectPoolFactory`.

- **`Bounded`** — `BoundedPool<T>`: без выделений памяти после прогрева.
- **`Linked`** — `LinkedPool<T>`: переиспользование за O(1), узел списка на каждую выдачу.

## `ObjectPoolFactory`

Точка сборки пулов: единственное место, которое знает конкретные реализации `IObjectPool<T>`.
Потребители (например, BulletHoles) получают готовый пул через конструктор и зависят
только от интерфейса. В игре реализацию выбирает параметр конфигурации `decalPool`.

- **`Create`<T>(…)`** — Создать пул выбранной реализации; параметры и ошибки — как у конструкторов реализаций.
  - ошибка `ArgumentOutOfRangeException`: Неизвестное значение `kind`.
- **`TryParse(…)`** — Разобрать имя реализации из конфигурации: `"bounded"` или `"linked"` (без учёта регистра).
  - результат: `true`, если имя известно.
