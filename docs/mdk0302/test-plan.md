# Система проверок: магазин и запас дробовика (МДК.03.02 ПЗ-2)

## 1. Объект и правила (Р1)
**Объект** — класс [`AmmoMagazine`](../../Assets/Game/Scripts/GunScript/AmmoMagazine.cs): магазин, запас, перезарядка
и подбор коробок. Зона ответственности — участок «Оружие и попадания» (EgorSad06).

**Вариант выполнения** — 1 по методичке: функция выделена в зоне ответственности без добавления логики. До ПЗ-2 эти
правила были частью `Weapon` (MonoBehaviour вместе с вводом, корутинами и `Time.time`) и отдельно не вызывались.
Логика перенесена в чистый C#-класс без изменения поведения; `Weapon` вызывает его и передаёт `Time.time`.
Поведение `Weapon` до и после выделения сверено по коду (раздел 6, ручные проверки М1–М6).

| | |
|---|---|
| Вход | настройки (вместимость, стартовый запас, предел, время перезарядки, бесконечный запас, «по одному»); события: выстрел, начать перезарядку (+ время `now`), продвинуть время (`Tick(now)`), прервать, подобрать коробку (`amount`) |
| Результат | `FireResult` (Fired / Empty / Blocked); `true/false` начала перезарядки; число перенесённых и взятых патронов; состояние `Magazine`, `Reserve`, `IsReloading` |
| Ошибки | недопустимые настройки → `ArgumentOutOfRangeException` с именем параметра (`Weapon` пишет `[ERROR][Weapon]` и выключается); коробка ≤ 0 → ничего не берётся |

**Проверяемые правила.** Источник ожидаемого результата (оракул) — требование спецификации 1.1
([requirements.md](../requirements.md), раздел 5.2), а не запуск программы. Числа — параметры дробовика из сцены
(магазин 2, запас 16, предел 40, перезарядка 0,9 с).

| Правило | Формулировка | Источник |
|---|---|---|
| П1 | Есть патрон в магазине и нет перезарядки → выстрел, магазин −1, запас не меняется | FR-WPN-01 |
| П2 | Магазин 0 → выстрела нет (`Empty`), счётчики не меняются; при запасе 0 перезарядка не начинается | FR-WPN-03.1 |
| П3 | Перезарядка начинается, только если магазин неполон, нет перезарядки и запас > 0 (или бесконечный); повторное `R` во время перезарядки игнорируется, таймер не перезапускается | FR-WPN-03, ОП-2 |
| П4 | Через 0,9 с после начала (граница включена) магазин = min(2, магазин + запас), запас уменьшается на перенесённое; до этого момента выстрел заблокирован, счётчики не меняются. Режим «по одному»: по 1 патрону каждые 0,9 с | FR-WPN-03 |
| П5 | Коробка добавляет min(amount, 40 − запас); остаток остаётся в коробке; при полном запасе — 0 | FR-WPN-04, ERR-04 |
| П6 | Прерывание перезарядки (смена оружия) — патроны не переносятся, перезарядку можно начать снова | FR-WPN-07 |
| П7 | Ошибочные данные: коробка ≤ 0 не меняет запас; магазин < 1, отрицательные запас, предел, время → ошибка с именем параметра | FR-WPN-04.1 |

FR-WPN-04.1 добавлено в спецификацию 1.1 при проектировании проверок: для ошибочного входа (отрицательная коробка,
неверные настройки) ожидаемого результата в 1.0 не было. Требование записано по смыслу ERR-06 (игра не закрывается),
а не подогнано под код: реакция `Weapon` на неверные настройки (журнал + выключение) добавлена вместе с требованием.

### 2.3 Переходы состояний
```
            TryFire (M>1)                 TryFire (M=1)
  Готово ───────────────► Готово   Готово ─────────────► Пусто (M=0)
  Пусто ── TryFire ─► Пусто (Empty, счётчики те же)               │ TryStartReload (R>0)
  Пусто ── TryStartReload (R=0) ─► Пусто (отказ)                   ▼
  Перезарядка ── TryFire ─► Перезарядка (Blocked)          Перезарядка
  Перезарядка ── TryStartReload ─► Перезарядка (отказ)       │  Tick(now ≥ конец) ─► Готово (перенос)
  Перезарядка ── CancelReload ─► Готово/Пусто без переноса   │  «по одному»: Tick ─► Перезарядка (+1) … ─► Готово
```
| Переход | Тест |
|---|---|
| Готово → Пусто → Перезарядка → Готово (ситуация С1 из ПЗ-1) | T18 |
| Перезарядка + выстрел → Blocked | T17 |
| Перезарядка + повторное `R` → отказ | T10 |
| Перезарядка + прерывание → без переноса, повторный старт | T19 |
| Пусто + `R` при запасе 0 → остаётся Пусто | T04 |
| Перезарядка «по одному» → (+1) → Готово; прерывание после первого; догон при долгом кадре | T37–T39 (добавлены по анализу покрытия) |

## 3. Тестовые данные (Р3)
Все данные — в коде тестов [`AmmoMagazineTests.cs`](../../Assets/Game/Tests/Editor/AmmoMagazineTests.cs): числа из
таблиц выше, параметры дробовика из сцены. Случайных данных нет. Состояние «магазин M» готовится через API
(выстрелы из полного магазина), без рефлексии. Файлов, учётных данных и персональных данных тесты не используют.

**Заглушка.** Системное время (`Time.time`) заменено параметром `now`: тест передаёт моменты 0; 0,5; 0,899; 0,9; 10 с.
*Что не проверяется:* что `Weapon` действительно передаёт `Time.time` каждый кадр (`TickReload` в `Update`), поведение
при паузе (`Time.timeScale = 0`) и реальной частоте кадров; ввод с клавиатуры и мыши; звук и анимация. Это закрыто
ручными проверками М1–М6 (раздел 6) и риском R5.

Скрытый набор данных преподавателя — **не получен**.

## 4. Запуск (из чистого клона)
```
git clone https://github.com/EgorSad06/BeerAndDragon.git && cd BeerAndDragon
git checkout 0302-pz02-<код>-v1
python tools/mdk0302/run_tests.py              # все EditMode-тесты, построчно — AmmoMagazineTests
python tools/mdk0302/run_tests.py --coverage   # + HTML-отчёт покрытия: build/mdk0302/coverage/Report/index.htm
```
Нужны Unity 6000.3.0f1 (путь — `--unity` или `UNITY_EXE`), Python 3, Git LFS. Unity с этим проектом не должен быть
открыт. В конвейере те же тесты выполняет задание **EditMode tests** (`.github/workflows/_unity-tests.yml`) на каждый PR
и push в рабочую ветку; упавший тест делает задание неуспешным (проверка `ci/check_test_results.py`).
