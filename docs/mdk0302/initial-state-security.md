# Исходное состояние и ранние ограничения безопасности: участок «Оружие и попадания»

Автор: EgorSad06 (<ФИО>). Общая часть для проекта — [environment.md](../environment.md); здесь — то, что нужно проверяющему именно для требований FR-WPN-01…07 и NFR-WPN-01/02.

## Как получить состояние для проверок
| Что проверяется | Состояние | Как получить |
|---|---|---|
| FR-WPN-01, 02, 04, 05 (автотесты) | исходный код и Unity 6000.3.0f1 | клон + `git lfs pull`; EditMode-тесты: `Unity.exe -batchmode -projectPath . -runTests -testPlatform EditMode` ([RUN.md](../RUN.md)). Данные тестов создаются в коде тестов, внешних файлов не нужно |
| FR-WPN-01…07 (вручную) | собранная игра, уровень `SampleScene` | `.\tools\pz01\build.ps1 -Mode Release` → запуск `build\release\BeerAndDragon.exe`. Дробовик и меч выдаются при старте (`Inventory.startingItems`), в магазине 2, в запасе 16 |
| FR-WPN-03.1 (нет патронов) | магазин 0, запас 0 | выстрелить 18 раз без подбора коробок (2 в магазине + 16 в запасе); коробки патронов стоят на уровне в известных местах (`LevelPickups`), к ним не подходить |
| FR-WPN-04 (коробка при полном запасе) | запас 40 | подобрать коробки до 40 или собрать Development-сборку и выставить `reserveAmmo` в инспекторе |
| FR-WPN-05.1 (неверный `decalPool`) | файл конфигурации | `ci\pz02\bad-pool-config.json`, запуск `-config ci\pz02\bad-pool-config.json` |
| NFR-WPN-01/02 | Release-сборка, воспроизводимый вход | `-batchmode -nographics -config ci\pz02\bounded-config.json -decalProbe 1000 -ciSmoke 1` → строка `[INFO][Probe]` в журнале |

Внешних систем, учётных записей и сетевых обращений на участке нет, учебный режим не нужен.

## Ранние ограничения безопасности
| Вопрос (методичка, п. 4.6) | Ответ для участка |
|---|---|
| 1. Какие данные или ресурсы нужно защищать? | Персональных данных и учётных записей нет. Защищать нужно **целостность поставки** (exe и `Managed/*.dll` — проверка SHA-256 в Release Gate) и **стабильность процесса**: участок не должен падать или бесконечно расти по памяти — число декалей ограничено 60 |
| 2. Откуда поступает недоверенный ввод? | (а) файл конфигурации `game-config.json` и путь `-config` — его может изменить пользователь; (б) аргументы командной строки (`-decalProbe N`); (в) ввод с клавиатуры и мыши. Конфигурация проверяется явно (неверное значение → `[ERROR][Config]`, код 2, без исключения); `-decalProbe` с нечисловым или ≤ 0 значением → `[ERROR][Probe]`, прогон не выполняется; ввод игрока — только нажатия, данных не несёт |
| 3. Кто имеет доступ к существенным действиям? | Игра локальная, однопользовательская: все действия доступны тому, кто запустил процесс. Существенные действия разработки (слияние в `main`, релиз, секреты CI) — только владелец репозитория; защита `main` и обязательные проверки — [repo-rules.md](../repo-rules.md) |
| 4. Какой ущерб реалистичен? | Ошибка в пуле или конфигурации может вызвать падение игры, рост памяти, «вечные» дырки или неверный урон (игровой ущерб). Злоупотребление — подмена `game-config.json` с огромными значениями: значения ограничены (`targetFps` 15..300, `decalPool` — перечисление). Подмена `Managed/*.dll` в поставке — вне модели угроз этой работы; обнаруживается проверкой SHA-256 |
| 5. Где хранятся секреты и что нельзя выводить в журнал? | На участке секретов нет. Секреты проекта — лицензия Unity (`UNITY_LICENSE/EMAIL/PASSWORD`) — только в GitHub Secrets, в репозиторий и журнал не попадают (gitleaks в CI). Журнал не выводит окружение процесса; в нём есть путь к журналу и аргументы запуска — не секреты, но с именем пользователя Windows в пути. Это допустимо для локального журнала, но журнал нельзя публиковать без просмотра |

Полная модель угроз и защитные меры — в последующих работах.
