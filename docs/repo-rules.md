# Правила репозитория

Репозиторий: <https://github.com/EgorSad06/BeerAndDragon>

## 1. Ветки
| Ветка | Назначение | Кто пишет напрямую |
|---|---|---|
| `main` | **защищённая** основная ветка: всегда собирается и проходит тесты | никто — только merge через PR |
| `release` | стабилизация перед релизом; релиз = тег `vX.Y.Z` | никто — только merge через PR |
| `debag`, `feature/<кратко>`, `fix/<кратко>` | рабочие ветки | автор |

## 2. Правила изменений
1. **Любое изменение `main` — только через Pull Request.** Прямой push запрещён настройкой защиты ветки (см. п. 5).
2. **Автоматические проверки обязательны.** PR нельзя слить, пока не зелёные:
   - `checks / Repo checks + lint + secrets` — структура проекта Unity (`.meta`, GUID, LFS), статический анализ C#,
     актуальность засеянных дефектов, поиск секретов (gitleaks);
   - `unity-tests / EditMode tests` — компиляция в Unity и EditMode-тесты.

   Подробно — [CI.md](CI.md). Тяжёлые проверки (мутации, диагностика, Release Gate) запускаются по запросу и на тег — они
   не блокируют каждый PR, чтобы не тратить минуты Actions.
3. **Независимое review значимых изменений.** Значимое изменение — всё, что меняет игровую логику (`Assets/Game/Scripts/**`),
   сцены/префабы, CI (`.github/`, `ci/`), требования (`docs/requirements.md`, `docs/mvp.md`).
   Такой PR одобряет **не автор** (1 approve). Без review можно сливать только документацию и опечатки.
   Ревьюер смотрит: соответствие требованию (ID в описании PR), тест на новую логику, отсутствие `UnityEditor` в рантайме,
   не потеряны ли ссылки в сцене (diff `.unity`).
4. **Описание PR по шаблону** [`.github/pull_request_template.md`](../.github/pull_request_template.md): что сделано,
   какие требования затронуты (ID), как проверить, чек-лист DoD.
5. **Сообщения коммитов** — в повелительном наклонении, что и зачем: `Add bounded object pool (SP-1)`, `Fix skateboard sinking into ground`.
6. **Конфликты сцен** (`.unity`) решаются автором PR в Unity, а не вручную в тексте; после решения — `python ci/check_repo.py`.

## 3. Definition of Done (DoD)
Изменение «готово», когда выполнено **всё**:

- [ ] Требование, которое реализует изменение, есть в [requirements.md](requirements.md) (ID указан в PR); если требования не было — добавлено.
- [ ] Код компилируется в Unity без ошибок и новых предупреждений; для новых файлов есть `.meta`.
- [ ] `python ci/check_repo.py` и `python ci/lint_cs.py` — без ошибок.
- [ ] Для новой логики есть автотест; для исправленного бага — тест, который его ловит. Все EditMode-тесты зелёные.
- [ ] Если логика покрыта засеянными дефектами — `ci/mutations.json` обновлён, `apply_mutation.py --check-all` проходит.
- [ ] Ручная проверка в игре по критерию требования (условия → действие → результат) выполнена.
- [ ] Сцена сохранена, ссылки в инспекторе не потеряны.
- [ ] Существенные операции пишутся в журнал (`GameLog`), ошибки не глотаются молча.
- [ ] Документация обновлена (`docs/`, README), если поменялось поведение, управление или запуск.
- [ ] PR одобрен независимым ревьюером (для значимых изменений), все обязательные проверки зелёные.

## 4. Пример применения правил
**PR `debag → main`: «Add combat, items, skate, knight visuals, CI pipeline and CodeMap»** (коммит `f6966ba`).

1. **Работа в рабочей ветке.** Изменения сделаны в `debag`, не в `main`.
2. **Проверки нашли проблему до слияния.** Перед открытием PR локально запущены те же проверки, что в CI:
   ```
   python ci/check_repo.py
   ERROR META-сирота (нет файла/папки): Assets/Game/Assets/PS1 Cans Asset Pack/Unreal Engine 5 Project/...
   Проверено файлов: 1401 | ошибок: 107
   ```
   В ветке было 107 `.meta` от пустых папок Unreal: git не хранит пустые папки, у другого участника Unity создала бы
   новые GUID и сломала ссылки. Ещё нашлись дубликат пака дробовика (две копии в разных папках)
   и попавшие в git служебные файлы (`*.slnx`, сцены `_Recovery`). Всё исправлено в том же PR,
   `.gitignore` дополнен — повторно такие файлы не попадут. Результат: `ошибок: 0`.
3. **Статический анализ** (`lint_cs.py`): 0 ошибок, 4 предупреждения W101 (имя класса ≠ имя файла в старых скриптах
   `MainKnight/`) — оставлены как известный долг, вынесены в резерв.
4. **Тесты и мутации**: 37 EditMode-тестов, 8 засеянных дефектов; `apply_mutation.py --check-all` — все применимы.
5. **Описание PR** заполнено по шаблону: что сделано, как проверить, чек-лист DoD с отмеченными пунктами.
6. **Review**: PR значимый (логика, сцена, CI) → нужен approve не автора; слияние — после зелёных `checks` и `unity-tests`.

## 5. Настройка защиты `main` (делает владелец репозитория)
GitHub → *Settings → Branches → Add branch ruleset* (или *Branch protection rule*), шаблон ветки `main`:

| Настройка | Значение |
|---|---|
| Require a pull request before merging | ✅ |
| Required approvals | 1 |
| Dismiss stale approvals when new commits are pushed | ✅ |
| Require status checks to pass | ✅ `checks / Repo checks + lint + secrets`, `unity-tests / EditMode tests` |
| Require branches to be up to date before merging | ✅ |
| Block force pushes / Restrict deletions | ✅ |
| Do not allow bypassing the above settings | ✅ (правила действуют и на админа) |

То же правило — для `release`. Названия проверок появляются в списке после первого запуска `PR checks`.
Для review нужен второй участник с правами *Write* (*Settings → Collaborators*).
